# Rufajx-DSH 内置 SolidWorks 2016 工具包

版本：1.0.0，2026-10-20。工具包已经接入客户端默认企业插件和安装资源检查。新旧员工、管理员账号共用相同安装资源，任务目录、报告、模型及历史版本仍按账号隔离。安装程序的生成与发布由总开发负责，本文不表示某个旧 EXE 已含本次改动。

## 员工使用方式

员工电脑需要已安装、注册且能够正常启动的 Windows x64 SolidWorks 2016。安装新版 Rufajx-DSH 并登录后，直接说明“请使用 SolidWorks 2016 建模……”即可，无需自己安装 Python、pywin32、MCP 或填写模型密钥。客户端不附带 SolidWorks 软件、许可证或收费附加模块；试用、缺模板、缺字体及许可提示会如实报告。

普通聊天不加载这两项工具的 schema、CAD 上下文和接口目录。真实主会话用户明确要求 SW 建模后加载，明确的 CAD 后续修改继续使用；转到其他任务或取消后移除。授权取原生人类消息，附件、引用、工具结果及子任务自述不能开启。首次请求使用原生同步 `agent/inbox/claimed` 事件取得待提交输入，**仅控制工具可见性**；执行仍要求已经提交的人类消息和有效公司账号。无须修改上游 Agent Loop。

原窗口及未保存模型不会自动被接管。修改原业务模型时应提供已保存文件；外部参考先通过原生已审查文件能力复制到当前工作目录。工作目录由宿主确定，不接受模型指定账户或进程。

## 能力组织

| 层 | 内容 | 加载方式 |
|---|---|---|
| 原生查询工具 `company_solidworks` | guide、detect、status、libraries、search、member、type、enum、recipe、evidence | 用户要求后出现，具体资料分页查询 |
| 原生执行工具 `company_solidworks_run` | 当前步骤完整 Python 代码、同会话常驻 SW2016 实例、finish交还、close明确关闭 | 每次调用经过原生工具审查及文件历史保护 |
| 本地接口目录 | 20 个类型库，1,817 个类型，24,148 条方法/属性记录，10,872 条常量 | 从本机 SW2016 类型库提取并固定 SHA256 |
| 核心建模接口 | 403 个类型，13,712 条方法/属性记录 | 指定库/接口/方法查询真实参数和类型 |
| 历史证据 | 112 份记录，含 35 份正式接受样例、956 项断言 | 同时保留失败、诊断、修正和适用限制 |
| 方法参考 | 已接受样例源码快照及哈希 | 只作参考，转换为当前 cad/sw 实例，禁止直接执行旧测试脚本 |

接口记录包含属性、重载和附加模块，**不是等量的独立功能，更不等于全部测试通过**。未全面验证的操作仍可查原生接口，在副本上逐步尝试；每次必须核对特征、几何、重建、保存和重开结果。目录未包含的方法可查询本机帮助或官方文档；UI-only 操作可使用已有专用电脑子任务，仍受原生停止和权限限制。

Pack and Go 仍未通过。复杂曲面、机械配合、钣金、焊件、工程图及加载项的具体覆盖边界参见 `preinstalled/solidworks/evidence/index.json` 和随包 evidence。不得将齿轮/凸轮的已通过样例推广为任意几何、自由拖动或动力学仿真均通过。

## 执行和清理

- 同账号、同真实会话和工作目录复用一个独立可见SW2016进程及Python/COM上下文。首次按实际启动PID对应ROT绑定，确认启动完成、24.x、空实例及所有权后建模；后续不再默认重启、关闭或从零生成模型。只对已验证专属实例设置UserControl=True以便宿主退出仍可查看，用户原窗口及未保存模型不接管、不隐藏、不修改。
- 先给简短计划，逐个有意义的步骤执行、核对真实几何/预览，再决定下一步。`stepTitle`供工具卡片显示；每次仍提交完整可审查代码。失败保留部分结果，后续先检查再修正，不盲目重复特征。完成默认保留窗口，finish交还但不关闭；只有最新真实用户明确要求关闭时才可close，未保存/未命名模型拒绝关闭。
- 同一Windows用户的CAD操作串行独占，空闲时释放执行锁而保留各自实例。活动记录核对PID与创建时间，未知残留操作阻止执行；同会话并发拒绝、不排队重放。关闭、崩溃或失联不自动重新启动；结果未知需新用户指令，显式finish在确认旧控制进程退出后才解除旧连接，仍保留未知结论。
- 代码权限等同原生已审查脚本，**不是 Python/操作系统沙箱**。没有新模型通道，所有模型及审查继续通过公司服务端。
- `company_solidworks_run` 纳入整工作目录修改前/后版本捕获，保护未就绪时拒绝运行。保护范围不扩展到全盘、外部装配引用或第三方缓存。
- 停止采用取消标记与 Python 检查；原生 COM 卡住时只对本批次拥有的进程句柄结束处理。未知结果不自动重放。未保存的自有模型尽力另存恢复副本，不能保证原生崩溃后的未保存操作可恢复。
- 每步前后将未保存模型另存唯一恢复副本，不重命名/关闭原模型。注销或EOF交还窗口，不覆盖之后用户手动修改。临时日志与自动恢复设置持久备份，启动后比较恢复；窗口交还时绑定实际进程句柄的等待器在它退出后再次比较恢复，避免SW缓存写回。其他来源的新修改保留，不强制覆盖。
- 子进程只继承运行必需环境变量，不传公司令牌及模型凭据。报告在账号私有目录，模型在当前任务文件夹。

## 离线资产与打包

源目录为 `preinstalled/solidworks/`。复用随包 Python 3.12.10；新增固定 pywin32 311 Windows x64 CPython 3.12 wheel，SHA256 与来源见 `dependencies.lock.json`，解包保留原许可证。2026-10-21 默认可见候选离线负载 777 个文件、27,918,688 字节（约 27.9 MB），没有第二份 Python，没有 SolidWorks 安装程序。

构建机在**独立/已关闭** runtime 上执行：

```text
node scripts/solidworks-runtime.mjs prepare <runtime>
node scripts/solidworks-runtime.mjs check <runtime>
```

也已接入 `Prepare-ClientPresets.ps1` 和 `Start-Dev.ps1`。prepare 使用本地锁定 wheel，不访问网络；每文件哈希写入 `rufa-solidworks.json`。更新先构造独立临时目录，验证后替换；失败恢复先前负载，禁止热替换正在运行的用户 runtime。

安装构建前 `apps/client/scripts/check-runtime.mjs` 检查内容；afterPack/解包后的 `verify-packaged-preinstalled.mjs` 再验证 payload 清单和企业插件字节。缺依赖、缺目录、文件变化或多出未知文件拒绝通过。客户端首次登录只加载随包文件，不运行 npm/pip，不下载依赖。生成安装程序前必须同步最新源码并重新 prepare。

## 本次验收及复现

- `tests/solidworks-toolkit.test.mjs`：9 项通过。真实人类授权、首次请求、子任务继承边界、普通聊天卸载、完整目录、证据哈希和失败时文件版本捕获。
- `tests/solidworks-runner-unit.py`：8 项通过。不启动 SW；验证路径边界、取消循环、日志限长、串行锁、退出写回/外部修改保留，以及只显示验证后的专属实例、等待启动就绪、身份/版本/空实例检查失败时不改变可见性。
- `tests/desktop-solidworks.test.mjs`：原生 Electron + 本机合成公司服务器 + 员工账号，通过工具动态加载、公司身份、原生审查和前后版本 SHA256。模型与 COM 响应为 mock，不把它当真实 CAD 验收。
- `tests/solidworks-live-smoke.mjs`：使用最终离线 payload 的真实 SW2016 24.5.0，50×30×10 mm 长方体，体积 15000 mm³，保存/重开/预览，共 14 项检查通过；独立进程退出，原 PID39288 保留。退出后另读注册表验证两项值和类型均恢复。


### 2026-10-21 默认可见与原窗口保护专项

`tests/solidworks-visible-live.py` 在独立 runtime 中新建一个未保存测试模型，作为不得改变的原有实例；再调用实际 runner 分别验证正常建模和中途停止。最终 SW2016 24.5.0 正常批次 17 项、停止批次 11 项断言通过，核对了专属 PID 的真实可见窗口、保存/重开/预览和停止恢复副本。两批前后保护模型的窗口位置/标题/最小化、文件路径/未保存状态、文档数、体积和可见性逐项一致；各测试实例及启动设置均完成清理，未操作用户业务模型，0 模型调用。


生命周期仍为**每次执行工具调用对应一个专属实例**，批次结束保存并关闭，下一批重新打开已保存文件。默认可见改动不包含整个任务常驻复用窗口；连续多批调用仍会开关窗口。测试同时显示保护哨兵与工作实例，不能把测试多窗口现象当作已实现任务级窗口复用。
