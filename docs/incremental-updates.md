# Windows 文件增量更新

0.3.0 将桌面入口与实际应用分离。`Rufajx-DSH.exe` 是固定、带原产品图标的原生启动器；`Rufajx-DSH-App.exe` 是 Electron 应用。账号、草稿、会话、员工工作文件仍在各自原有目录，不属于更新集合。

## 从旧版迁移

0.2.x 仍读取原来的 `latest.yml` 并下载完整 NSIS 安装包，首次迁移不可变成旧程序尚不支持的增量协议。新安装包收到旧程序的 `--updated /S` 后主动显示安装阶段和真实解压进度，沿用原安装目录并在完成后启动新客户端。旧卸载与新文件落地之间，旧快捷方式可能短暂找不到目标；安装窗口在这段时间持续可见。不能宣称首次迁移也免重装。

## 后续更新

1. 登录前从固定公司 HTTPS 地址读取新版描述，核对版本及签名目标清单。
2. 对本机受管文件逐项核对，保留未变化的文件；只请求缺失或变化文件的内容。同一内容去重，已完整下载并核验的对象可复用。
3. 原生更新窗口显示后，应用才退出。桌面入口在更新中显示进度，不启动半更新的程序。
4. 变化文件进入同盘事务区，保存原文件，再替换目标。只允许删除上一份可信清单中明确移除的文件，未知文件保留；旧受管文件被外部修改时不猜测覆盖删除。
5. 校验、提交版本记录后启动应用。安装中断可按持久记录回滚或完成恢复，恢复资料不足或冲突时停止，不把失败当成功。

这属于**文件级增量**：大文件改变时仍下载整个该文件，不承诺二进制块级差分。大型离线浏览器、Python、Remotion 等未变化依赖继续原地使用，全部能力和离线依赖仍包含在完整安装包中。启动器或更新协议自身需要升级时可回退完整安装路径。

## 发布与信任

协议见 [contract.md](contract.md)。旧完整包与新增量描述使用同一个原子版本指针，先核对所有产物后再切换。历史版本和内容对象保留，已开始的下载不会因发布新版而改字节。

目标清单以 RSA3072 / SHA256 PKCS#1 v1.5 签名，客户端、原生启动器和服务端分别校验；每个文件还有 SHA256、SHA512 与大小。公钥随程序和服务端部署，私钥仅在构建账户下由 Windows DPAPI 加密保存。该内容签名不是 Windows Authenticode 发布者证书。

完整安装包先生成已签名文件清单，再写入 `.rufa-update/current-manifest.json` 与最小 `current.json`，为下一次升级提供可信旧集合。基线不包含安装器摘要，避免安装器对自身内容产生循环依赖。稳定启动器、其配置、卸载器和事务状态不得进入文件增量集合。

## 参考实现资料

采用了常见桌面软件将下载、应用替换、启动入口与恢复分开的思路，没有引入新的安装框架或替换 Electron。参考 [Electron Builder 更新说明](https://www.electron.build/v26/docs/features/auto-update/)、[Velopack 增量包说明](https://docs.velopack.io/packaging/deltas) 和 [VS Code Windows 安装与更新说明](https://code.visualstudio.com/docs/setup/windows)。下载差分本身不能证明免除全量安装，本方案单独验证文件是否真正原地复用。

最终安装、故障恢复、耗时和公开分发验收以对应版本 `release/windows/<version>/evidence/` 的实际报告为准。

## 0.3.0 实测边界

最终完整包在独立身份下新装 120.94 秒、覆盖安装 251.21 秒，68,999 文件路径/大小一致，实际中途进度 957 次，卸载后业务哨兵保留。这是单机测试，不是所有员工电脑的速度保证。

完整增量夹具保留全部实际离线资源：68,995 个受管文件，只替换测试中变化的 2 个文件（247,185,940 字节），23 个未变化且大于 10 MiB 的文件保持原文件身份和修改时间。重复点击桌面入口显示更新进度，完成后自动打开新版；准备阶段 79.36 秒、原生安装阶段 135.98 秒。传输使用内存模拟，时间不包含互联网下载。单独的原生 7 项测试覆盖真实中途强杀后的冷恢复、同一版本重试、签名/载荷损坏、运行锁和真实 Windows junction 拒绝。

发布服务器可从已验证旧安装包复用内容对象，并用一次性传输差分在私有目录重建完全相同的新完整安装包。`publish-client-release.py --server-artifacts` 再次逐项核对大小与摘要后复制到不可变版本目录；所有对象完备且服务检查通过才切换版本指针。该上传优化不改变客户端文件级协议，也不能作为客户端下载节省量。此次 0.2.3 → 0.3.0 发布传输补丁为 11,195,576 字节，最终完整安装包仍为 628,659,998 字节。
