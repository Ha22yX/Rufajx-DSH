# 电脑操作与视频制作预装

## 分发内容

- Windows 桌面操作：`dsh-computer-use-win` **0.4.3**，固定 npm integrity；对应源码 `c0ad0ed88c3207839f25fedb0dead5a347b2b71b`。
- 视频制作：`haidrrrry/claude-remotion-skill` 固定 `1dcbe5e3fc6cf970bd10d3cc05f0a8a5d19d0383`。完整 SKILL、references、theme 及引用的示例源码/音效生成脚本随包提供；演示成片不参与运行。
- `@rufa/dsh-remotion-bundle` 使用原生技能目录。只常驻短描述，制作/编辑视频、动画、字幕时加载完整技能，遵守渲染、查看关键帧、修正后交付的原始流程。
- Remotion **4.0.537**、React **19.2.0**、CLI/renderer/bundler/transitions/motion-blur/google-fonts、Windows 编码组件，以及 Chrome Headless Shell **157.0.8080.0** 固定分发。员工使用时不运行 npm、不临时下载浏览器、不需要 Claude 账号。

## 账号默认值

生产版和开发版共用初始化入口，按服务器与账号隔离，分别一次迁移、之后保留修改和停用。不读取管理员当前账号作为动态模板，不复制其凭据、聊天、草稿或个人路径。

电脑操作默认全部24工具；屏幕边缘/提示条开启、鼠标突出显示关闭、远程与录屏可见、顶部提示、`Rufa智能体正在控制电脑`、操作结束800ms收起、Esc停止，无额外快捷键。提示只在当前会话实际有桌面工具时注入，要求操作电脑时优先使用，先观察再操作并检查结果。原生 MCP 工具审查、公司身份与写入租约保持，禁用时不假报能力。桌面实际仍是本机Windows桌面，不是服务器远程控制。

## 打包流程

1. 按现有流程准备固定 Harness 和独立 Node。
2. 构建机执行 `scripts/Prepare-ClientPresets.ps1 -Runtime <runtime> -NpmCli <npm-cli.js>`。依赖下载仅在构建阶段执行，npm install scripts关闭，源码/浏览器SHA256核对。
3. `package:win`/`package:dir` 的 `check-runtime.mjs` 校验全部预装内容；`extraResources` 明确包含原生runtime、公司插件、Node、固定服务器配置及Remotion嵌套node_modules。
4. `scripts/verify-packaged-preinstalled.mjs` 作为 afterPack，在实际输出 resources 中检查插件、视频依赖与 app.asar 内编译好的预设。缺任何一项就阻止产包，解包验收复用同一检查。

新功能不能只加开发profile。所有预设代码随应用进入安装包；员工只需安装、登录，默认值在首次账号初始化时应用。已有账号保留其历史文件和后续偏好。

## 本地渲染入口

`company-tools/remotion/runner.mjs` 通过原生已审查命令工具调用。技能加载时提供固定Node与runner绝对路径，无额外模型服务。`init`仅接受空目录，`render`输出H264、`still`渲染关键帧，`probe`检查编码/时长，`frame`从真正成片抽帧；默认拒绝覆盖既有文件，显式`--overwrite`才覆盖。高级原生CLI仍在包内。渲染依赖为共享只读运行资产，项目源码与输出在当前账号工作文件夹，不给每个项目安装一份依赖。

这是新增的视频创作运行时，和视频预览的直接解码内核独立；不重新启用预览转码。

## 专用电脑子任务与桌面进度

主会话通过 `company_computer_task` 把明确的电脑任务交给原生独立子会话。电脑工具的截图、控件与详细结果留在子会话；原生完成通知将简短结果交回主会话。主会话的模型工具清单不再重复加载24个桌面工具。没有删除桌面能力，也不裁剪主会话原历史；子任务仍使用公司模型通道与原生审查。

进度复用固定电脑插件的 Windows 原生提示层，不依赖 DSH 窗口是否在前台。最终参考为2026-10-20的 `task-progress-translucent.html`：380px宽、约140px高、13px圆角的一体卡片；顶部深色控制栏，下方任务名、当前步骤、状态和简短说明。用户后续反馈原24%灰底在浅色窗口上难以阅读，现用约63%不透明深灰色（160/255），保留约37%背景透出及背景模糊；最新字体候选将辅助文字改为13px近白色、当前步骤16px加粗、Esc及停止12px，去掉文字阴影，按物理像素对齐并使用灰阶抗锯齿，不使用ClearType彩边或逐字硬描边。长内容适当增高，无历史步骤、计数、百分比、计时或演示控件。“Esc 停止”独立单行排版。提示不接收鼠标、不会抢走焦点。用户原有的位置、Esc停止和远程/录屏可见设置继续生效。最新字体候选尚未发布，具体测量范围及已知问题见下节。

用户随后要求在下半透明区域增加真实背景模糊，覆盖原参考的无模糊设定；仅背景模糊，不降低文字/图标透明度，也不垫不透明底板。完成/停止由原生子任务清理结果产生，最多显示2秒；`presentationTask()` 的终态回执与 `activeTask()` 的输入控制租约分开，展示回执不能清除停止事件或恢复电脑输入。

背景模糊窗口保持在原文字层之下，只在卡片下半可见，随位置、缩放、淡出、录屏偏好及销毁同步。实测Accent模糊忽略普通HRGN裁切，导致方角溢出；改用DWM原生圆角、关闭系统边框，左右/底部内缩2px，顶部延伸藏在不透明头栏下，避免底角突块和竖直白线。系统保留柔和圆角阴影；不声称所有边界外像素完全透明。圆角/边框/模糊API不支持时隐藏模糊窗口，保留半透明提示。已在Windows11 26200验证真正桌面合成与动态背景，未把单一Windows版本的验证当作所有系统兼容保证。原生 `completed` 只表示回合正常结束，故用“已结束”而非业务成功宣称，出错显示“未完成”，用户中止显示“已停止”。

子任务可选择固定短意图（例如“搜索内容”“下载文件”）。准备阶段明确显示准备，实际调用时结合工具动作，等待判断时显示核对结果；不把计划、点击成功或工具返回等同于业务目标已完成。任务短标题经控制字符、凭据、路径、网址等过滤，不从完整任务正文截取；说明使用固定员工用语。浮层不复制窗口标题、网址、文件路径、输入文字或截图。

`scripts/computer-progress-runtime.mjs` 对锁定的0.4.3源码进行有完整性检查的可重放适配，资源在 `preinstalled/desktop-video/progress/`。开发启动、构建准备及打包后核验共同覆盖该扩展，不能仅在个人profile上生效。原生窗口和停止功能使用独立runtime验收，模型流转另用本机模拟网关验证，不代表已完成真实业务任务。

## 2026-10-20 字体清晰度候选（未发布）

- `Progress.cs` 仅调整文字布局、字号、测量及绘制；标签矩形与字号落在整数物理像素，绘制期间恢复为单位变换，文字只画一次，之后还原原图形状态。卡片形状、透明度、模糊实现、停止与输入控制逻辑不变。源码SHA256：`61033c58ec37145fde5b5d949a51b05319ccc5a39c5a1f3fc5e285d18ecdb34d`。
- 原实现并非先画低分辨率图片再放大。实拍照片也不足以判断显示器PPI或Windows分辨率错误。独立PowerShell宿主探针实测进程DPI设置成功，因此不声称发现DPI感知初始化失败。
- 原生离屏绘制覆盖100%、125%、150%、175%、200%、250%、300%及1600–1603宽度。对当前步骤采样区域的高亮字形alpha掩码，旧实现在100%/200%有363/784个差异像素，新实现全部为0，且每档有实际非零字形；这不是整卡逐像素一致、实体多显示器验收或清晰度提升百分比。长中英文内容在顶部/底部的换行与停止标签另做可视检查。
- 独立真实PowerShell提示层的任务文本、透明度、单行停止、焦点保持、鼠标穿透与停止释放检查通过。完整进度专项8项中7项通过、1项已有DWM背景动态更新断言失败；同一机器的0.2.3基线同样失败，不能声称背景动态更新已修复。模糊程度、圆角外无亮缝等检查仍通过。试验性模糊改动全部撤回，未放宽测试断言。
