# Windows 安装性能与真实进度

本次只改变安装与覆盖安装过程，不裁剪客户端、插件、技能、离线浏览器或媒体组件，不改变员工操作方式。生产应用目录、账号资料、工作文件和服务端权限规则保持原有边界。

## 已查明的等待

固定 electron-builder 26.15.3 的原始 NSIS 模板先将约 2.1 GiB、68,985 个文件解到 C 盘临时目录，再逐文件复制到实际安装目录。跨盘复制时，解压插件已结束，进度缺少有用变化。

覆盖安装还有第二条路径：旧卸载器的 `un.atomicRMDir` 将安装目录逐文件移到 `$PLUGINSDIR/old-install`，失败再执行 `un.restoreFiles`。安装在 D 盘而临时目录在 C 盘时，原本的重命名也会变成跨盘读写。必须保留这条失败恢复路径，不能直接删除旧文件或绕过原卸载器。

## 安装组件

- `apps/client/scripts/prepare-installer.mjs` 校验固定 builder 版本、模板摘要、压缩配置与本地组件摘要，在独立 `build/rufa-nsis` 生成模板副本。不修改 `node_modules` 或只读上游。
- 文件直接解压到 `$INSTDIR`。保留原生按用户安装、卸载、注册、快捷方式与更新缓存流程。
- 修改后的同源 Nsis7z 19.00 DLL 返回真实解码结果和错误标志；损坏、截断、缺包、写入失败都不能继续成功登记。
- 进度使用 64 位真实解压字节，最多每 100 ms 更新一次。字节处理完尚不代表 CRC/写入成功，因此解码返回成功前百分比上限为 99。后续明确显示缓存、登记等阶段。
- 官方源码、许可证及可重放构建补丁随安装包提供，员工不需要额外安装编译工具或联网下载依赖。

覆盖安装使用单独的 `RufaUpgradeTemp` 本地安装组件：先只读核对实际文件路径长度，在安装盘上选择可写的短祖先目录，创建当前用户私有的随机临时目录，仅给旧卸载子进程设置该目录的 TEMP/TMP。父进程环境不变，旧卸载器的移动、失败恢复、重试和原地回退函数保持原版。处理期间显示明确阶段和滚动进度，不把无法测量的旧文件处理伪装成百分比。成功只清理自己创建的目录，不跟随目录链接；失败保留残留恢复资料。没有满足路径长度限制的安全同盘目录时，明确标示兼容模式并沿用原生临时目录流程；非法安装根或新目录校验失败时停止安装。

完整包验收曾发现：仅在安装目录旁创建长 GUID 临时目录，会把 Inspector 的最长文件路径拉长到 284 字符，使原生卸载器搬移失败并恢复。该中间包未发布。最终方案使用紧凑的 128 位随机名称、实际路径预算和最短可写祖先；旧方案的真实长路径失败及新方案成功都有独立复现记录。

## 压缩兼容性不可省略

打包端 7za 24.09 默认可能选择旧解码器不支持的 ARM64 过滤器。这解释了旧安装实际少两份 ARM64 附带文件的问题；这些文件仍必须保留，不用删除内容掩盖问题。

客户端 `electron-builder.env` 固定 `ELECTRON_BUILDER_7Z_FILTER=BCJ`。它是可逆的压缩处理，不修改任何安装文件。准备阶段拒绝缺失、重复或冲突配置。最终产物还需核对内嵌归档 Method，不得含 ARM64。修改压缩参数后不可复用旧 `.nsis.7z` 缓存。

## 验收方式

`scripts/extract-installer-payload.mjs` 从最终 EXE 的真实内嵌归档读取偏移、大小、压缩方法和摘要，提取原样归档，不重压缩。

`scripts/verify-windows-installer.mjs` 用唯一产品身份、独立 D 盘路径和同一生产安装宏构建验收安装器。原样复用上述归档，只增加测试进度观测；不会运行或卸载用户的真实 Rufajx-DSH。实际新装、覆盖安装、文件核对、源码核对和精确卸载均需完成。每次回调还断言实际输出目录就是目标安装目录。NSIS 的编译输入路径应保持较短，避免 MSIX 物理路径前缀超过原生编译器路径限制。

如果复用 `--dir` 产物进行 `--prepackaged`，先核对并补齐正式 `app-update.yml`；不能把缺少更新源的预览目录直接当成可发布包。必须执行 `scripts/verify-packaged-preinstalled.mjs` 的完整门禁。

## 本机测量记录

2026-10-20 第一轮完整实装：新装 109.27 秒，覆盖安装 332.28 秒。68,985 份文件的路径/大小、核心二进制 SHA256 和九份安装源码 SHA256 均相符；871 个真实中途进度样本，输出目录均为独立 D 盘目标。没有模型调用，没有改动真实客户端。此轮覆盖安装尚使用跨盘旧文件搬移，作为后续同盘优化的本机基线，不作为其他电脑耗时保证。

证据：`release/windows/0.2.2/evidence/full-install-before-upgrade-optimization.json`。最终同盘覆盖安装结果及公开发布状态以 `docs/client-releases.md` 为准。

最终完整包实装：新装 84.60 秒，覆盖安装 201.27 秒。相对上述本机覆盖基线少 131.01 秒（39.4%）；缓存、存储和安全软件会影响其他机器及不同轮次，不能外推为固定耗时。全部 68,985 份文件（2,264,518,546 字节）路径/大小及核心摘要一致，十一份安装源码摘要一致；672 个首次安装进度样本均直接写入目标盘，没有解码成功前的假 100%。精确卸载后测试目录已不存在，业务哨兵保留，真实客户端未改动、没有收费模型调用。

最终报告：`release/windows/0.2.2/evidence/full-install.json`。同源提取器十种不同原生用例（含真实 5 GiB、两种 ARM64 过滤器结果）、升级组件十种不同用例（含长路径、恢复、权限与原生兼容回退）及五项准备门禁通过。最终 EXE 的内嵌应用归档 SHA256 为 `5691b3f0604916294afe70fc85b4c7e9675839ef84472cbd892c77260ec3a8f5`，与运行时验收包相同；只重建安装包装层，没有再次改变应用文件。
